# STARBURST v2 — Architecture & Contracts

Phaser 3.90 + Vite. Native 640×360, pixel-art. Read `docs/STYLE.md` first.

## Layout
```
src/config.js            W,H,DEPTH,FONT constants
src/game.js              Phaser config  (+ window.__game in dev)
src/scenes/              Boot, Preload (bakes art, sets up generated audio), MainMenu, Game, GameOver (+ extra scenes registered in scenes/index.js)
src/art/palette.js       THE palette
src/art/bake.js          text-map -> texture baker
src/art/contract.js      every texture key + size the code may use   <-- the interface between art and code
src/art/placeholder.js   auto labelled placeholder for contract keys that aren't drawn yet
src/art/sprites/*.js     pixel art (ships, projectiles, enemies, fx, icons, ui)
src/fx/Fx.js, Background.js
src/ui/text.js (pxText), widgets.js, Hud.js, UpgradeScreen.js
src/systems/Save.js (persistence), sfx.js (play sounds), quality.js (graphics quality), display.js (pixel scaling),
                         virtualKeys.js + gamepad.js (pad/touch -> key presses), + gameplay systems
src/scenes/SysOverlay.js always-on top scene: FPS counter, gamepad bridge, touch controls, auto-pause on blur
src/objects/             Player, Enemy types, bullets, WaveManager (gameplay)
tools/render-sprites.mjs LOOK at sprites;  tools/shot.mjs headless screenshots of the running game
tools/qa.mjs             smoke + leak test of every flow (see docs/QA.md)
```

## Interfaces (stubs exist for all of them so every module runs standalone)
- **Fx** (`src/fx/Fx.js`) — `new Fx(scene)`; `explosion(x,y,size,palette)`, `hitSpark`, `shockwave`, `debris`, `floatText`, `shake`, `hitStop`, `flash`, `grazeSpark`, `muzzle`, `slowmo`, `update(dt)`, `destroy()`. See the stub for exact signatures. The Game scene creates one and passes it to everything that needs it.
- **Background** — `new Background(scene,{biome})`, `update(dt,intensity)`, `setBiome(i,fadeMs)`, `pulse(strength)`, `destroy()`.
- **Hud** — `new Hud(scene)`, `update(state)` every frame (state shape documented in the stub), `announce(title,sub)`, `toast(text,color)`, `destroy()`.
- **UpgradeScreen** — `new UpgradeScreen(scene, options, onPick)`; option = `{id,title,desc,icon,tag}`.
- **widgets** — `createPanel`, `Button`, `MenuNav`, `createBar`, `createSlider`, `createToggle` (stub shows the contract).
- **GameOver** scene — `scene.start('GameOver', { score, wave, stats:{graze,maxCombo,kills} })`; it calls `save.recordRun`.
- **Scenes** — `scene.start('Game')` reads `save.ship` and `save.difficulty`; Game ends with `scene.start('GameOver', ...)`.
- **Textures** — only keys in `src/art/contract.js`. Static sprite: `add.image(x,y,key)`; multi-frame: `add.sprite(x,y,key,frameIndex)` or `.play(key)` for ones with `fps` (animations are registered under the same key as the texture). Variants: `bullet_orb_m_amber`.
- **Audio** — everything is generated by code (no audio files; see `docs/AUDIO.md`). Sfx keys (recipes in `src/audio/sfx/`, baked into Phaser's audio cache by `systems/synthSfx.js`): play with `sfx(scene,key,{vol,rate,jitter})` from `systems/sfx.js`, which applies per-key cooldowns, voice caps, pitch jitter and a global voice budget (table in `sfx.js`); menus use `uiSfx(scene,'hover'|'select'|'back')`. Music volume from `save.musicVolume`.
- **Music** (`systems/music.js` over `src/audio/engine.js`, Web Audio, never `scene.sound` for music): tracks are sequenced synth patterns (`title-music sector1..4 boss boss-final`), `playMusic(key,{fadeIn,fadeOut,restart,intensity,boss})` crossfades, `playSting(key)` (`sting-boss|clear|gameover|upgrade|victory`), `stopMusic(ms)`, `setMusicVolume(v)`, `duck(reason,on)` (`pause|upgrade|gameover|launch`), `setIntensity(0..1)` (opens layers), `setBossMode(bool)` — all no-op safe. In Game, `this.audio` (GameAudio) picks the sector track, handles duck/intensity automatically from scene state, crossfades to the boss theme via `setBossMode(on, final)`, and exposes `bossWarning()` and `waveClear()`.
- **Reactivity** (`systems/audioReact.js`): `getBass()`, `getLevel()`, `getPulse()` (0..1 beat envelope), `onBeat(cb)` → unsubscribe fn (beats come from the music sequencer, on the audio clock). Dev: `window.__audio` exposes these modules plus `music(key)`, `sfx(key)`, `sting(key)`, `list()` for auditioning.
- **Save** (`systems/Save.js`) — the only place that touches localStorage.
- **Online** (optional, off unless the build sets `VITE_API_URL`) — `systems/net.js` is the only code that calls `fetch`; `runlog.js` records a run (per-wave time / hull lost / hits, hull damage by source, lethal hit), `telemetry.js` sends sessions, errors and runs (with an offline outbox), `leaderboard.js` adds the world boards, `scenes/menu/CallsignPanel.js` + `scenes/gameover/WorldRank.js` are the UI. Hit sources come from `origin` in `objects/patterns.js` (set by enemy / boss updates, carried by the Sequencer, stamped on bullets). Backend, schema, tests and the anti-cheat limits: `server/README.md`; what is collected: `docs/PRIVACY.md`.
- **Seeded RNG** (`systems/rng.js`) — for anything a Daily Run should reproduce, draw from a named stream instead of
  `Math.random`: `const rnd = rngStream('mySystem')` at module level, then `rnd()`. Unseeded (normal runs) it *is*
  `Math.random`; `seedRun(seed)` (done by `scenes/run/RunMeta.js` for Daily Runs) re-seeds every stream. Streams already
  used: `spawns` (WaveManager), `enemies` (Enemy.spawn), `upgrades` (rollOptions). Also `createRng(seed)` for a local
  generator, `dateKey()`, `dailySeed()`. Keep cosmetic randomness (particles, sfx) on `Math.random`.
- **Meta layer** — `systems/meta.js` (credits, hangar upgrades `applyMeta(player)`, ship unlocks, run mode
  `setRunMode('normal'|'daily')`), `achievements.js` (`checkAchievements(run)`, `onUnlock(fn)`), `leaderboard.js`
  (top 10 per mode), `runResult.js` (`settleRun` once per GameOver). In-run hook: `Game.create` makes
  `this.run = new RunMeta(this)` (applies upgrades, polls achievements, sector-complete recap after bosses, death
  moment) and calls `this.run.update(dt)`. Player gets `grazeBonus` (read in `collisions.js`).
- **Scene changes** — use `wipeTo(scene, key, data, { edge })` (`scenes/cine/wipe.js`): the shared pixel wipe drawn by
  the always-on `Wipe` scene. Extra scenes: `Intro` (first launch only, `save.seenIntro`), `Hangar`, `SectorComplete`
  (over the paused Game), overlays `MenuAchievements`, `MenuRecords`. Dev: `window.__meta` (`systems/metaDebug.js`).

## Rules
1. Pixel-perfect: integer positions, scale 1, `roundPixels`. Text only via `pxText`. Colours from `COLORS`/`PALETTE`.
2. Depth values from `DEPTH`. No magic numbers for layout that relate to screen size: use `W`/`H`.
3. Clean small modules (aim < 300 lines/file). No giant scenes. Comments explain *why*.
4. Performance: pool bullets and particles; avoid per-frame allocations in hot loops; 60 fps with ~300 bullets on screen.
5. Don't commit `tmp/`, `node_modules/`, `dist/`.
6. Keep every file you own importable even when other modules are still stubs.

## How to run / look at things
- `npm install` if `node_modules` is missing (or symlink the main checkout's). Dev server: `npx vite --port <YOUR PORT>` (run in background).
- URL `http://localhost:<port>/?scene=Game` (or `MainMenu`, `GameOver`, …) jumps straight into a scene (dev only).
- `node tools/shot.mjs --url http://localhost:<port>/?scene=Game --wait 2500 --out tmp/<you>/x.png` then **Read the PNG**. `--eval "<js using __game>"` + `--then-wait ms` to drive state; `--seq "ms::js::file;;ms::js::file"` for several shots. Errors thrown in the page are printed. Always look at your screenshots; never ship what you haven't seen.
- `node tools/render-sprites.mjs [module]` for sprite sheets (pixel authors).
